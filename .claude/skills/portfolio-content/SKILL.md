# 포트폴리오 콘텐츠 작성

## 1. 대상 독자와 목표 정하기
먼저 아래 두 가지를 정한다. 섹션 순서와 문구 톤이 전부 여기서 결정되기 때문이다.
- **대상 독자**: 채용 담당자 / 프리랜서 클라이언트 / 동료·커뮤니티 중 누구인가
- **원하는 행동**: 이력서 다운로드, 이메일 연락, 작업 의뢰 등 방문자가 마지막에 할 일 하나

사용자가 말하지 않았으면 가장 그럴듯한 쪽으로 가정하고 문서에 "가정"이라고 적는다.

## 2. 섹션 구성
기본 섹션(ID는 고정 — 개발자가 그대로 앵커로 쓴다):

| ID | 섹션 | 필수 | 핵심 |
|----|------|------|------|
| `hero` | 첫 화면 | ✔ | 이름, 한 줄 정체성, 주요 행동 버튼 1개 |
| `about` | 소개 | ✔ | 3~4문장. 무엇을, 누구를 위해, 어떻게 하는지 |
| `projects` | 프로젝트 | ✔ | 대표작 3~6개. 가장 강한 것을 맨 앞에 |
| `skills` | 기술/도구 | | 그룹별로 묶음. 숙련도 막대그래프는 쓰지 않는다(근거 없는 숫자로 보임) |
| `experience` | 경력/학력 | | 최신순, 항목당 성과 1~2줄 |
| `contact` | 연락처 | ✔ | 이메일 + 주요 링크(GitHub, LinkedIn 등) |

채용 대상이면 `projects` → `experience` 순, 클라이언트 대상이면 `projects` 다음에 서비스/후기를 둔다. 새 섹션이 필요하면 추가하되 ID를 영문 소문자로 정한다.

## 3. 문구 원칙
- 상투어 대신 사실: "열정적인 개발자" ✗ → "3년간 결제 시스템을 만들어 온 백엔드 개발자" ✔
- 프로젝트는 **문제 → 내가 한 일 → 결과** 순서. 결과에 수치가 있으면 쓰되, 사용자가 준 수치만 쓴다.
- 한 문장은 짧게. 첫 화면 한 줄 정체성은 20자 안팎.
- 모르는 정보는 지어내지 않고 `[TODO: 무엇이 필요한지]`로 남긴다.

## 4. 출력 형식 — `_workspace/01_strategist_content.md`

```markdown
# 포트폴리오 콘텐츠
## 변경 사항            ← 재실행 시에만
## 기본 정보
- 이름 / 직무 / 대상 독자 / 원하는 행동 / 톤(예: 차분·전문적, 유쾌·실험적) / 언어(한국어, 영어 병기 여부)
## 섹션 순서
hero, about, projects, ...
## hero
- title / subtitle / cta_label / cta_link
## about
(본문)
## projects
- id: kebab-case
  title / summary(한 줄) / problem / role / result / tags[] / link / repo / image
## skills / experience / contact
...
## TODO 및 사용자 확인 질문
```

프로젝트 필드명(`id, title, summary, problem, role, result, tags, link, repo, image`)은 개발자의 `projects.js`와 1:1로 대응하므로 바꾸지 않는다.
